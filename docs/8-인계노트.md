## 1. 사용자와 일하는 방식 (꼭 지킬 것)

사용자가 직접 요청한 방식입니다. 자세한 내용은 `CLAUDE.md` 맨 위에 있습니다.

- 사용자는 시키는 대로 그대로 따라 한다. **쉽고 자세하게, 한 번에 한 단계씩** 설명한다.
- 매 답의 끝에 늘 붙인다:
  1. **남은 단계 목록** (끝난 것은 ✅)
  2. **다음에 사용자가 보낼 명령** (그대로 복사해 보낼 수 있는 한 줄)
  3. **'나중에 해도 되는 개선 작업' 목록** (없으면 없다고)
- 비밀번호·토큰은 **채팅창에 받지 않는다.** 코드·깃에도 넣지 않는다(대시보드 계정 화면이나 환경 변수에만).
- 사용자가 PR 을 "합쳐 줘" 라고 하면 기본 브랜치에 합치고, **서버 업데이트 명령**을 알려 준다.

## 2. 구조

```
사이트들 ──수집기(sources/)──▶ SQLite(db.py: 저장 + 규칙 분류 classify.py + 같은 공고 묶기 dedup.py)
                                   │
                                   ▼  사람마다 조건 비교(matching.py)
                        텔레그램·메일(notify/) ◀── pipeline.run_cycle()  ◀── scheduler.py (08:10·12:40·18:20 무렵)
                                   ▲
              Flask 대시보드(web/) ─┘   (같은 컨테이너, 앞에 Caddy 가 https)
```

- **수집하는 곳:** 모어덴·덴트포토(로그인 필요, 모어덴은 브라우저 Chromium), 잡알리오, 하이브레인넷, 나라일터, **병원 채용 게시판 67곳**
  (`dentmoa/data/institutions.json` 에서 `"watch": true` 인 항목).
- **분류는 AI 없이 규칙(정규식)** 으로 한다. 규칙을 바꾸면 `classify.CLASSIFIER_VERSION` 을 올린다.
  회귀 시험: `tests/fixtures/classify_cases.json`(98건), `classify_cases_adv.json`(279건).
- **받는 사람:** `settings['people']` — 키 `p1`(사용자 본인), `p2`(아내). 처음 별명은 SH·JY 였고, 사용자가 대시보드에서 별명을 바꿔 쓴다.
  코드와 DB 는 별명이 아니라 키(p1·p2)로 구분하니 별명은 신경 쓰지 않아도 된다.
- 파일별 설명은 `CLAUDE.md` 의 '구조'에 있다.

## 3. 서버 운영

| 항목 | 내용 |
|---|---|
| 서버 | Lightsail 인스턴스 `dentmoa` (서울, Ubuntu 24.04, 512MB + 스왑 2GB), 고정 IP `3.39.124.154`, 방화벽 22·80·443 |
| 코드 위치 | 서버의 `~/dentmoa` (git clone. 원격 주소에 GitHub **읽기 전용 토큰**이 들어 있음) |
| 데이터 | `~/dentmoa/data` (SQLite·로그인 쿠키), `~/dentmoa/backups` (매일 새벽 4시 30분 KST 백업, 14개 보관) |
| 설정 | `~/dentmoa/deploy/.env` (주소, 첫 비밀번호용 설치 코드) |
| 업데이트 | 기본 브랜치에 합친 뒤, 사용자가 SSH 창에서 `cd ~/dentmoa && sudo bash deploy/update.sh` |
| 연결 지킴이 | `deploy/netwatch.sh` 를 cron 이 2분마다 실행 → 인터넷이 끊기면 4분 뒤 네트워크 재시작, 10분 뒤 재부팅. 기록 `/var/log/dentmoa-netwatch.log` |

**Claude 는 서버에 직접 접속할 수 없습니다.**
- 서버 일은 사용자가 Lightsail 콘솔의 **브라우저 SSH 창**에 명령을 붙여넣고, 결과를 **사진**으로 보내 주는 식으로 한다.
- 브라우저 SSH 창은 **한글이 네모(□)로 깨진다.** 그래서 서버에서 돌릴 진단 명령은 **영어·숫자로만 출력**되게 만든다.
- 한글로 확인해야 하면 대시보드 화면(한글이 잘 보임)의 사진을 부탁한다. 예: **상태** 화면의 '병원별 결과'.
- 명령은 한 줄로, 복사해서 그대로 붙여넣을 수 있게 준다.

자주 쓰는 서버 명령은 [6. 문제 해결](6-문제해결.md)에 있습니다. 로그 보기, 다시 시작, 백업, 비밀번호 분실, 토큰 만료 등.

## 5. 개발하는 법 (새 Claude 용)

- **시험:** `python -m pytest`. 네트워크 없이 도는 시험 수백 개다. 사이트 수집기는 `tests/fixtures/sites` 의 실제 화면을 줄인 HTML/JSON 으로 시험한다(개인 정보는 지움).
- **실제 사이트에 접속해야 할 때:** Claude 작업 환경의 네트워크 허용과 환경 변수가 필요하다 → [7. 개발 세션 설정](7-개발-세션-설정.md).
  - 작업 환경은 해외에 있어서, 한국 정부·병원 사이트 몇 곳은 자주 끊기거나 아예 막힌다(국군수도병원은 가끔 끊김, 계명대 동산병원은 접속 불가).
  - 이럴 때는 여러 번 다시 시도하거나, 서울 서버에서 확인한다(위 3장 방식).
- **일의 종류별로 고칠 곳**

  | 하고 싶은 일 | 고칠 곳 |
  |---|---|
  | 사이트 화면이 바뀌어 '화면 구조가 바뀐 것 같아요' 경고가 옴 | `dentmoa/sources/<사이트>.py` + `tests/fixtures/sites` + `tests/test_sites.py` |
  | 병원 게시판 추가·주소 변경·끄기 | `dentmoa/data/institutions.json` (`watch`, `recruit_url`, `title_filter`, `shared`, `fetch`, `note`) + README 의 게시판 수 |
  | 공고 분류가 틀림 | `dentmoa/classify.py` + `classify_cases*.json` 에 사례 추가 + `CLASSIFIER_VERSION` 올리기 |
  | 알림 문구·모양 | `dentmoa/notify/format.py` |
  | 대시보드 화면 | `dentmoa/web/` (템플릿은 `web/templates`) |
  | 서버 설치·업데이트 | `deploy/` (install.sh, update.sh, netwatch.sh, docker-compose.yml) |

- **브랜치와 PR:** 작업 브랜치에서 고치고 → 시험 통과 → PR → (사용자가 원하면) 기본 브랜치 `claude/dentist-job-alert-app-xmcl6s` 로 합침 → 서버 업데이트 명령 안내.
- **마무리:** 이 문서의 [7. 작업 기록](#7-작업-기록)과 `CLAUDE.md` 에 무엇을 왜 바꿨는지 한두 줄 남긴다.

## 6. 하지 않기로 한 것과 그 이유

| 결정 | 이유 |
|---|---|
| 분류에 AI 를 쓰지 않음 | 비용 없이, 늘 같은 결과. 규칙 + 회귀 시험 377건으로 관리 |
| 서버를 7달러(1GB)로 올리지 않음 | 512MB 로 충분했고, 실패한 날은 다음 수집 때 따라잡는다. 모어덴 실패가 며칠씩 계속될 때만 다시 검토 |
| 두 사람용으로 서버를 두 벌 만들지 않음 | 수집과 메모리가 두 배가 됨. 한 벌에서 사람마다 조건만 따로 둔다 |
| 강북삼성병원 게시판 끔 | 새 채용 사이트(ninehire)의 보안 검문소가 자동 접속을 일부러 막음. 우회하지 않는다. 의사 공고는 하이브레인넷·잡알리오에도 올라온다 |
| 계명대 동산병원 게시판 끔 | 작업 환경에서 접속 불가, 사용자 결정(2026-10-11). 하이브레인넷으로 모인다 |
| 강원대치과병원·삼성창원병원 끔 | 사용자 요청(강원·창원으로 옮길 생각 없음). 강원의 다른 게시판은 켜 두고 알림 조건의 지역으로 거른다 |
| AWS 계정을 새로 만들어 크레딧 받기 | 약관 위반(크레딧은 한 사람 한 계정). 지원팀 답변으로 이 계정은 크레딧 대상이 아님을 확인 → 월 약 5.5달러를 카드로 낸다 |

## 8. 사용자용: 새 Claude 에게 일을 맡기는 법

### 처음 한 번 준비 (새 Claude 계정에서)
1. **GitHub 연결:** claude.ai 의 Claude Code 에서 GitHub 를 연결할 때, 이 저장소 주인인 **`newdentmoa` GitHub 계정으로 로그인**해서 연결한다.
   - 다른 GitHub 계정을 쓰고 싶으면, 먼저 `newdentmoa` 로 GitHub 에 로그인해 저장소 **Settings → Collaborators** 에서 그 계정을 초대한다.
   - 그다음 Claude GitHub 앱이 저장소에 설치돼 있는지 확인한다(<https://claude.ai/connect-github>).
2. **새 대화 열기:** 저장소 `newdentmoa/dentmoa` 를 골라 새 대화를 연다. 브랜치는 기본 브랜치 그대로.
3. 실제 사이트에 접속해야 하는 일(사이트 화면이 바뀜 등)이면 [7. 개발 세션 설정](7-개발-세션-설정.md)대로 네트워크와 환경 변수를 넣는다. 평소 수정은 필요 없다.

### '할 일' 예시
- 알림이 이상할 때: `오늘 이런 알림이 왔어(아래 붙여넣기 또는 사진). 원인을 찾아서 고쳐 줘.`
- 분류가 틀렸을 때: `이 공고가 '치과의원 · 봉직의'로 나왔는데 '대학병원 · 임상교수'가 맞아. 제목: … / 원문 링크: …`
- '사이트 화면 구조가 바뀐 것 같아요' 경고: `모어덴 화면이 바뀐 것 같다는 경고가 왔어. 실제 화면에 맞게 수집기를 고쳐 줘.` (7장 준비 필요)
- 기능 추가: `알림 시각을 하루 4번으로 늘리고 싶어` / `특정 병원을 알림에서 빼고 싶어`
- 질문만: `코드는 고치지 말고, 덴트모아가 하루에 사이트를 몇 번 읽는지만 알려 줘.`
