# 6. 문제 해결

자주 생기는 문제와 해결 방법입니다. 해결이 안 되면, 화면에 나온 오류 메시지나 로그를 복사해서 Claude Code 세션에 보여 주며 물어보세요.
(로그에는 비밀번호가 들어 있지 않습니다. 단, **비밀번호나 토큰을 채팅창에 직접 쓰지는 마세요.**)

---

## 서버에 명령을 입력하는 방법 (공통)

아래에 나오는 명령은 모두 서버의 SSH 창에 입력합니다.

1. <https://lightsail.aws.amazon.com> → `dentmoa` 인스턴스 → **연결** 탭 → **SSH를 사용하여 연결**
2. 명령을 복사해 붙여넣고 **Enter**
3. `sudo` 로 시작하는 명령은 관리자 권한으로 실행됩니다. 비밀번호를 묻지 않는 것이 정상입니다.

## 알림이 안 와요

위에서부터 차례로 확인하세요.

1. **대시보드가 열리나요?**
   열리지 않으면 아래 [대시보드가 안 열려요](#대시보드가-안-열려요)를 먼저 봅니다.
2. **상태** 화면 → **출처별 마지막 수집**
   - 최근 시각에 **성공**이 있으면 수집은 잘 되고 있습니다.
   - **실패**가 있으면 **자세히**를 눌러 이유를 봅니다. (로그인 실패 → [아래](#로그인에-실패했어요-모어덴덴트포토))
3. **계정·연결** → 텔레그램 **테스트 메시지 보내기**, 메일 **메일 테스트**
   - 테스트도 안 오면 [3. 텔레그램 설정](3-텔레그램-설정.md#잘-안-될-때), [4. 메일 설정](4-메일-설정.md#잘-안-될-때)을 봅니다.
4. **알림 조건** → 위쪽에서 알림이 안 오는 사람(SH·JY)을 고른 뒤 **○○의 알림** 에서 **텔레그램으로 받기** / **메일로 받기**가 켜져 있나요? **계정·연결**에 그 사람의 채팅 ID·받는 주소가 저장돼 있나요?
5. **상태** → **알림 미리보기** — 조건에 맞는 새 공고가 있는지 봅니다.
   - 비어 있다면 **알림이 오지 않는 것이 정상**입니다. 맞는 새 공고가 없으면 알림을 보내지 않습니다.
   - 조건이 너무 좁을 수 있습니다. **알림 조건**에서 저장하면 "최근 30일 공고 중 N건이 해당돼요" 가 나오니 숫자를 확인해 보세요.
   - 새 공고가 없을 때도 알림을 받고 싶다면 **알림 조건** → **○○의 알림** → **새 공고가 없어도 '새 공고 없음' 알림 받기**를 켭니다.
6. 한 번 알린 공고는 다시 알리지 않습니다. 이미 받은 공고인지 **공고** 화면에서 확인해 보세요.
7. **메일**은 스팸함, **텔레그램**은 봇을 차단하거나 대화를 지우지 않았는지 확인합니다.
8. 그래도 모르겠다면 [로그](#로그-보기)를 봅니다.

## 로그인에 실패했어요 (모어덴·덴트포토)

알림에 **"로그인에 실패했어요. 비밀번호가 바뀌었는지 확인해 주세요"** 가 오거나, **상태** 화면에 로그인 실패가 보일 때입니다.

> 로그인에 실패하면 덴트모아는 **계정 잠김을 막으려고 같은 아이디·비밀번호로는 하루 한 번만** 다시 시도합니다.
> 아래처럼 **계정·연결**에서 비밀번호를 고쳐 저장하면 다음 수집 때 바로 다시 시도합니다. 그동안 놓친 글은 로그인이 되면 따라잡습니다.

1. **컴퓨터나 휴대폰으로 그 사이트에 직접 로그인**해 봅니다.
   - 사이트에서 비밀번호를 바꿨다면 → 대시보드 **계정·연결**에 새 비밀번호를 넣고 저장합니다.
   - 로그인할 때 "비밀번호 변경 안내", "휴면 계정", "자동 입력 방지(보안 문자)", "본인 확인" 같은 화면이 나오면, 직접 로그인해서 처리해 주세요. 처리한 뒤에는 덴트모아도 다시 로그인할 수 있습니다.
2. **모어덴**은 **카카오 로그인이 아닌 아이디·비밀번호 로그인** 정보가 필요합니다.
3. **계정·연결** → **출처별 연결 테스트**에서 그 사이트 버튼을 눌러 확인합니다.
4. 직접 로그인은 잘 되는데 덴트모아만 계속 실패한다면, 사이트의 로그인 화면이 바뀌었을 수 있습니다. 아래 "사이트 화면 구조가 바뀐 것 같아요" 와 같은 방법으로 수리를 요청합니다.

> 아이디·비밀번호를 서버 설정 파일(`deploy/.env`)에 넣었다면, 화면에서 바꿀 수 없다고(“서버 환경변수에서 바꿔 주세요”) 나옵니다.
> 이때는 `sudo nano ~/dentmoa/deploy/.env` 로 파일을 열어 그 줄 맨 앞에 `#` 을 붙이고(`Ctrl+O` → `Enter` 로 저장, `Ctrl+X` 로 닫기),
> `cd ~/dentmoa/deploy && sudo docker compose up -d` 로 다시 시작한 뒤 화면에서 입력하세요. 어렵다면 Claude에게 도움을 요청하세요.

## "사이트 화면 구조가 바뀐 것 같아요" 경고

알림에 **"사이트 화면 구조가 바뀐 것 같아요. 프로그램 수리가 필요해요"** 가 오면,
그 사이트가 화면 모양을 바꿔서 덴트모아가 공고 목록을 찾지 못한다는 뜻입니다. **사용자가 잘못한 것이 아니고, 프로그램을 고쳐야 합니다.**
(덴트모아는 사이트 화면을 보고 공고를 읽기 때문에, 사이트가 화면을 바꾸면 읽는 방법도 바꿔야 합니다.)

**고치는 방법**

1. Claude Code 에서 새 세션을 엽니다. (저장소 `newdentmoa/dentmoa`)
   - Claude 작업 환경에서 실제 사이트에 접속할 수 있어야 합니다. 설정 방법: [7. 개발 세션 설정](7-개발-세션-설정.md)
2. 첫 메시지로 이렇게 보냅니다. (사이트 이름과 출처 이름은 경고에 나온 것으로 바꾸세요.)

   > 덴트모아 알림에 '모어덴: 사이트 화면 구조가 바뀐 것 같아요' 경고가 왔어. CLAUDE.md 를 읽고 `python -m dentmoa probe moreden` 으로 실제 화면을 저장해서 수집기를 지금 구조에 맞게 고쳐줘. 테스트도 추가하고 main 에 반영해줘.

   | 사이트 | 출처 이름 (probe 뒤에 쓰는 말) |
   |---|---|
   | 모어덴 | `moreden` |
   | 덴트포토 | `dentphoto` |
   | 잡알리오 | `alio` |
   | 하이브레인넷 | `hibrain` |
   | 나라일터 | `gojobs` |
   | 병원 채용게시판 | `hospitals` |

3. 수리가 끝나면 서버에서 [업데이트](#업데이트-방법)를 합니다.

**고치기 전까지:** 같은 경고가 계속 오는 것이 불편하면 **알림 조건** → **수집** → **확인할 사이트**에서 그 사이트를 잠시 꺼 둘 수 있습니다. (고친 뒤 다시 켜세요.)

> 접속 실패·화면 구조 경고는 같은 사이트가 **연속 3번**(약 하루) 실패했을 때만 옵니다. 한두 번 실패는 다음 수집 때 놓친 글까지 따라잡으니 알리지 않습니다.
> "사이트에 접속하지 못했어요 (일시적일 수 있어요)" 는 사이트가 잠시 멈췄거나 느린 경우입니다. 며칠씩 계속되지 않으면 기다리면 됩니다.

## 업데이트 방법

프로그램이 고쳐지거나 새 기능이 생기면 서버에서 아래 명령 한 줄로 업데이트합니다.

```
cd ~/dentmoa && sudo bash deploy/update.sh
```

- 최신 코드를 받고 → 프로그램을 다시 만들고 → 다시 시작합니다. 몇 분 걸립니다.
- 공고·설정·계정 정보(`data/`)와 서버 설정(`deploy/.env`)은 그대로 남습니다.
- 끝나면 대시보드를 새로고침합니다.

### 업데이트가 안 돼요

- **`Authentication failed`, `Invalid username or password`, `Repository not found`**
  → GitHub 토큰이 만료됐습니다. [2장 1단계](2-설치하기.md#1단계-github-읽기-전용-토큰-만들기)대로 새 토큰을 만든 뒤, 아래 명령의 `<새토큰>` 을 바꿔서 실행하고 다시 업데이트합니다.
  ```
  cd ~/dentmoa && git remote set-url origin https://<새토큰>@github.com/newdentmoa/dentmoa.git
  ```
- **`Not possible to fast-forward`, `Your local changes … would be overwritten`**
  → 서버의 코드 파일이 바뀌어 있습니다. 서버에서 코드를 직접 고친 적이 없다면, 아래 명령으로 GitHub의 코드와 똑같이 맞춘 뒤 다시 업데이트합니다. (공고 데이터 `data/` 와 설정 `deploy/.env` 는 지워지지 않습니다.)
  ```
  cd ~/dentmoa && git fetch && git reset --hard @{u}
  ```
- **개발 브랜치로 설치했는데 프로그램이 main 에 합쳐졌어요** (`-b claude/…` 로 설치한 경우)
  → 아래 명령으로 main 으로 옮긴 뒤 업데이트합니다.
  ```
  cd ~/dentmoa && git fetch origin && git checkout main
  ```

## 백업

공고·관심 표시·설정·계정 정보는 모두 서버의 `~/dentmoa/data/dentmoa.sqlite3` 파일 하나에 들어 있습니다.

- **자동 백업:** 설치할 때 매일 새벽 4시 30분(한국 시간)에 자동으로 백업하도록 등록됩니다. 백업 파일은 `~/dentmoa/backups/` 에 쌓이고, **최근 14개**만 남습니다.
- **지금 바로 백업:**
  ```
  cd ~/dentmoa && sudo bash deploy/backup.sh
  ```
- **백업 목록 보기:**
  ```
  ls -lh ~/dentmoa/backups
  ```

**백업에서 되돌리기** (파일 이름의 날짜·시각은 실제 백업 파일로 바꾸세요)

```
cd ~/dentmoa/deploy
sudo docker compose stop app
sudo cp ../backups/dentmoa-20261009-043000.sqlite3 ../data/dentmoa.sqlite3
sudo rm -f ../data/dentmoa.sqlite3-wal ../data/dentmoa.sqlite3-shm
sudo chown 1000:1000 ../data/dentmoa.sqlite3
sudo docker compose start app
```

**서버째 백업하기 (권장)**
위 백업 파일은 같은 서버 안에 있어서, 서버가 통째로 망가지면 함께 사라집니다.
Lightsail 인스턴스 → **스냅샷** 탭 → **자동 스냅샷**을 켜 두면 서버 전체를 매일 저장해 둡니다. (스냅샷에는 작은 저장 요금이 붙습니다. 화면에서 확인하세요.)

## 대시보드 비밀번호를 잊었어요

서버에서 아래 명령으로 새 비밀번호를 정합니다.

```
cd ~/dentmoa/deploy && sudo docker compose exec app python -m dentmoa set-password
```

- "새 대시보드 비밀번호" 를 물으면 새 비밀번호(8자 이상)를 입력하고 **Enter**, 한 번 더 입력하고 **Enter** 합니다.
- **입력하는 동안 화면에 글자가 보이지 않는 것이 정상입니다.**
- 비밀번호를 바꾸면 다른 기기의 로그인은 모두 풀립니다. 새 비밀번호로 다시 로그인하세요.

> 처음 화면에서 **설치 코드**를 묻는다면: 설치 화면 마지막에 나온 6자리 숫자입니다.
> SSH 창에서 `cd ~/dentmoa && sudo grep SETUP_CODE deploy/.env` 로 다시 볼 수 있습니다.

비밀번호를 알고 있고 바꾸고만 싶다면 → 대시보드 **상태** 화면 맨 아래 **대시보드 비밀번호 바꾸기**

## 대시보드가 안 열려요

1. Lightsail 인스턴스 상태가 **실행 중**인지 확인합니다. **중지됨**이면 ⋮ → **시작**을 누릅니다. 서버가 켜지면 덴트모아도 저절로 켜집니다.
2. 서버에서 프로그램이 켜져 있는지 확인합니다.
   ```
   cd ~/dentmoa/deploy && sudo docker compose ps
   ```
   `app` 과 `caddy` 가 모두 `Up` (또는 `running`) 이어야 합니다. 아니면 켭니다.
   ```
   cd ~/dentmoa/deploy && sudo docker compose up -d
   ```
3. 인증서(https) 오류라면 → [2장의 https 문제 해결](2-설치하기.md#https-주소가-열리지-않거나-인증서-오류가-나요)
4. **서버 IP가 바뀌었다면** (고정 IP를 떼었거나 새로 붙인 경우) 주소를 다시 만듭니다. 새 주소가 화면에 나옵니다.
   ```
   cd ~/dentmoa && sudo bash deploy/install.sh auto
   ```

## 로그 보기

로그는 프로그램이 무엇을 했는지 적어 둔 기록입니다. 문제를 찾을 때 씁니다.

```
cd ~/dentmoa/deploy
sudo docker compose logs -f app            # 실시간으로 보기 (나가기: Ctrl+C)
sudo docker compose logs --tail 100 app    # 최근 100줄만 보기
sudo docker compose logs --tail 50 caddy   # 웹 서버(https) 기록
sudo docker compose ps                     # 켜져 있는지 보기
sudo docker compose restart app            # 다시 시작
```

대시보드의 **상태** 화면에서도 실행 기록과 사이트별 결과를 볼 수 있습니다.

## 서버 비용 확인 · 잠시 멈추기 · 그만두기

**비용 확인**
AWS 콘솔 맨 위 검색창에 `Billing` 을 검색 → **결제 및 비용 관리** → **청구서**에서 이번 달 요금을 볼 수 있습니다.
**예산(Budgets)** 메뉴에서 "월 1만 원을 넘으면 메일 받기" 같은 예산 알림을 만들어 두면 안심이 됩니다.

**잠시 멈추기**
Lightsail 인스턴스의 ⋮ → **중지**. 다시 쓸 때는 ⋮ → **시작** (덴트모아도 저절로 다시 켜집니다).
> ⚠️ Lightsail은 **중지해 두어도 요금이 계속 나옵니다.** 요금을 멈추려면 아래처럼 지워야 합니다.

**완전히 그만두기 (요금 멈추기)**

1. 남겨 둘 것이 있다면 먼저 확인합니다. (관심 공고 등)
2. Lightsail → 인스턴스 `dentmoa` → ⋮ → **삭제**
3. Lightsail → **네트워킹** 탭 → 고정 IP `dentmoa-ip` → **삭제** (연결되지 않은 고정 IP는 요금이 나옵니다)
4. **스냅샷**을 만들었다면 **스냅샷** 탭에서 함께 삭제합니다.
5. 다음 달 청구서에서 요금이 더 나오지 않는지 확인합니다.

## 그 밖의 문제

| 증상 | 해결 |
